# AutoDroids Chat Widget

Brand skin, location picker and quick-action chips for the **CloseBot** chat widget.
One engine, one config per dealer, built into self-contained per-dealer bundles.

```
src/engine.js        the widget — no dealer baked in, never linked directly
dealers/<name>.json  one file per dealer: account key, palette, stores, chips
build.js             engine + dealer config  ->  dist/<name>.js
sri.js               prints the ready-to-paste install tag for each bundle
test/                headless suites, run against every built bundle
```

Each dealer gets their **own URL, own version pin and own SRI hash** — totally separate
from the dealer's point of view — while a bug is fixed once in the engine.

---

## Install — what a dealer pastes

One tag, head or body. It loads CloseBot itself, so the site needs no separate CloseBot tag.
Generate the current snippet rather than copying an old one:

```bash
node build.js && node sri.js v1.0.0
```

**Never link `src/engine.js`.** It has no dealer config and no account key.

---

## Adding a dealer

1. Copy an existing `dealers/*.json` and edit it.
2. `node build.js` — fails loudly on a missing `closebotSource` or duplicate location tags.
3. `bash test/run.sh` — the suites run against every bundle, so a bad config fails here
   rather than on a dealer's site.
4. Commit, tag, `node sri.js <tag>`, send the snippet.

Keys starting with `_` are documentation only and are stripped at build time.

| Key | What it does |
| --- | --- |
| `closebotSource` | **Required.** CloseBot account key |
| `locations` | `{name, tag}` per store. `[]` = no location handoff, one = fixed rooftop, 2+ = picker |
| `actions` | `[label, message]` quick-action chips |
| `brand` / `brandDark` / `ink` / `tint` | Palette — take these from the dealer's own theme CSS |
| `font` / `fontUrl` | Font stack and the Google Fonts href (`''` loads nothing) |
| `avatar` | Header avatar image (`''` = none) |
| `storageKey` / `urlParamName` | Per-dealer so two dealers never collide |
| `locationMessage` | Routing message sent on selection. `{name}` and `{tag}` substituted |
| `urlParam` | `true` also stamps `?<urlParamName>=<tag>` — see Routing |
| `darkCanvas` | `true` keeps CloseBot's dark chat background |

`window.CW_CFG` declared before the script still overrides anything, per site.

## Routing to the droids

**CloseBot's widget exposes no tagging API.** Verified against `cb.js` — the outbound payloads are:

```js
POST /session/:id/message      { message }        // cb.js:2198
POST /session/:id/page-visit   { url, title }     // cb.js:1860
POST /session                  { sessionId }
```

No custom fields, no tags, no `data-*` config. **Tagging is applied server-side in CloseBot**;
the widget's job is to hand it a signal.

The qualifying droid is shared across accounts and only ever **listens** for a store — it must
never ask, because on a single-rooftop account that question is nonsense. So the widget decides
whether a signal exists at all:

| `locations` | Behaviour |
| --- | --- |
| `[]` | No picker, no signal — account has no location handoff |
| one | No picker; stamped silently so quick actions still carry it |
| two+ | Picker |

Nothing is ever announced on load, so a page view cannot fabricate a message — and therefore
cannot fabricate a lead.

**Channel 1 — message text (always on).** Sends `locationMessage`; quick actions append the store
in parens. The droid reads it. Depends on language parsing.

**Channel 2 — URL param (`urlParam: true`).** Stamps `?<urlParamName>=<tag>` via
`history.replaceState`, which CloseBot **patches** (`cb.js:1887`) and reports through
`/page-visit`. Machine-readable and never in the transcript, but it mutates the visible URL and
shows in analytics paths. Off by default.

## Why unminified, and why SRI

The `integrity` hash means the browser refuses to execute the file if a single byte differs, so a
compromise of the repo or the CDN cannot inject anything into a dealer's site.

That only works if we control the exact bytes served — which is why bundles point at
`dist/<name>.js` and **not** jsDelivr's auto-minified `.min.js`. That output is generated by
jsDelivr, so the hash can't be computed from our source, and if they change their minifier the
hash breaks and the widget silently stops loading.

Gzip does the real work: ~17 KB raw, **~5.9 KB** on the wire. Minifying would save around 1.5 KB
after gzip — not worth the fragility.

`.gitattributes` pins line endings to LF. Without it a Windows checkout can rewrite the files to
CRLF and silently invalidate every hash.

## Releasing

jsDelivr caches git tags permanently. Never repoint a published tag; cut a new one.

```bash
node build.js && bash test/run.sh
git add -A && git commit -m "..."
git tag v1.0.1 && git push origin main --tags
node sri.js v1.0.1        # send the dealer the new URL AND the new hash
```

The URL and the hash are a matched pair. A stale hash means the browser silently refuses to
execute and chat never appears, with nothing useful in the console.

**Do not ship `@main`** — branch refs are cached ~12 h, so you can't tell which version a page
is running. The repo must be **public** for jsDelivr to serve it.

## How it hooks into CloseBot

The widget is CSS-variable driven, so most of the skin is overriding its theme tokens
(`--cb-color`, `--cb-bg`, `--cb-soft-bg`, `--cb-text`, `--cb-muted`, `--cb-border`, `--cb-input-bg`).

Two things worth knowing:

1. **`--cb-color` is set inline** (`panel.style.setProperty`, `cb.js:1479`), so every token
   override needs `!important` to win the cascade.
2. **The bubble class is `cb-msg`, not `cb-message`.** Dealer is `.cb-msg.bot`, customer is
   `.cb-msg.lead`.

Token overrides are safe — they're CloseBot's public theming surface. The structural selectors are
internal and could break if CloseBot ships a rewrite. The script is identical across source keys —
only runtime config differs — so a change affects every dealer at once. Re-fetch and diff:

```bash
curl -s "https://api.closebot.com/scripts/cb.js?source=<key>" | grep -oE "cb-[a-z0-9-]+" | sort -u
```

Our own CSS uses a `cw-` / `--cw-` prefix, deliberately **not** `--ad-*`, which live-inject
already publishes.
